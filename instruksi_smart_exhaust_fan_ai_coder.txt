1. KONSEP HARDWARE SMART EXHAUST FAN
============================================================

Hardware:
- ESP32
- Relay 2 channel
- 1 servo
- 2 limit switch untuk posisi duct:
  - DUCT OPEN
  - DUCT CLOSED

Fungsi fan:
1. Fan dapat OFF/ON.
2. Fan mempunyai dua arah:
   - INTAKE
   - EXHAUST

Wiring konsep:
- Relay channel power:
  - mengontrol power utama fan.
- Relay channel direction:
  - COM ke terminal AC switching.
  - NC = EXHAUST.
  - NO = INTAKE.
- Hanya satu jalur direction yang boleh aktif.
- Servo menarik tali mekanisme duct.
- Duct:
  - tarik 1x = OPEN
  - tarik 2x = CLOSE
- Limit switch digunakan sebagai feedback posisi duct.

ATURAN PALING PENTING:
- JANGAN mengubah direction ketika motor fan masih berputar.
- Sebelum direction berubah, fan HARUS OFF.
- Setelah direction berubah, beri settling delay sebelum fan ON.
- Fan hanya boleh ON ketika duct sudah terbukti OPEN.
- Fan OFF harus menyebabkan duct ditutup otomatis.
- Semua operasi harus dikontrol oleh state machine, bukan sekadar if/else langsung dari MQTT.

============================================================
3. BEHAVIOR UTAMA
============================================================

A. FAN ON

Ketika target:
power = ON
direction = INTAKE/EXHAUST

Urutan:

1. Pastikan fan OFF.
2. Pastikan duct OPEN.
3. Jika duct belum OPEN:
   - aktifkan servo untuk membuka duct.
   - tunggu OPEN limit switch.
   - hentikan servo.
4. Pastikan direction sesuai target.
5. Jika direction berbeda:
   - fan harus OFF.
   - tunggu motor berhenti.
   - ubah relay direction.
   - tunggu relay settling delay.
6. Setelah duct OPEN dan direction benar:
   - nyalakan fan.
7. Actual state menjadi RUNNING.

Fan TIDAK BOLEH ON sebelum duct OPEN terkonfirmasi.

------------------------------------------------------------

B. FAN OFF

Ketika target:
power = OFF

Urutan:

1. Fan OFF.
2. Tunggu motor berhenti.
3. Aktifkan servo untuk CLOSE duct.
4. Tunggu CLOSE limit switch.
5. Hentikan servo.
6. Actual state menjadi IDLE.

Jika duct sudah CLOSED, jangan menjalankan servo lagi.

------------------------------------------------------------

C. GANTI DIRECTION SAAT FAN MENYALA

Contoh:
INTAKE -> EXHAUST

WAJIB:

1. Fan OFF.
2. Tunggu motor berhenti.
3. Ubah relay direction.
4. Tunggu settling delay.
5. Pastikan duct masih OPEN.
6. Fan ON kembali.
7. Actual state RUNNING.

DILARANG:
Fan ON -> relay direction berubah -> fan tetap ON.

Tujuan:
- mencegah motor mendapat hentakan reverse secara langsung.
- mencegah kontak relay switching ketika motor masih aktif.

============================================================
4. MQTT COMMAND HANDLING
============================================================

MQTT adalah transport komunikasi, bukan state machine.

Jangan langsung mengeksekusi command MQTT pada handler callback.

MQTT hanya memperbarui desired state / command queue.

Gunakan pendekatan state-aware.

Contoh:
Jika menerima:

ON
OFF
ON
OFF
ON

jangan selalu menjalankan lima siklus fisik penuh.

Target terbaru harus menjadi acuan state machine.

Contoh:
Saat ESP32 sedang OPENING_DUCT kemudian menerima OFF:
- jangan memaksa relay.
- selesaikan/abort operasi yang aman sesuai state machine.
- target menjadi OFF.
- lanjutkan menuju OFF secara aman.

Jika menerima command baru ketika transisi sedang berjalan:
- jangan membuat kondisi relay konflik.
- jangan memotong operasi berbahaya.
- prioritaskan safety.
- setelah safe point tercapai, evaluasi desired state terbaru.

Gunakan queue/state handling sesuai pola arsitektur IoT existing jika sudah tersedia.

============================================================
5. FAIL-SAFE ESP32 RESTART
============================================================

Saat ESP32 boot/restart:

WAJIB:
1. Semua output masuk kondisi aman.
2. Fan harus OFF.
3. Jangan langsung menghidupkan motor.
4. Inisialisasi limit switch.
5. Baca actual duct position dari limit switch.
6. Ambil desired state terakhir dari backend/database melalui mekanisme existing.
7. Masukkan desired state tersebut ke state machine.
8. Jalankan recovery secara perlahan dan aman.

Contoh database terakhir:
power = ON
direction = INTAKE

Jika duct CLOSED:
BOOT
-> FAN OFF
-> OPENING_DUCT
-> OPEN limit detected
-> CHANGING_DIRECTION jika perlu
-> relay settle
-> STARTING_FAN
-> RUNNING

Tidak boleh:
BOOT -> langsung relay ON -> motor menghentak.

Jika desired state OFF:
BOOT
-> FAN OFF
-> pastikan duct CLOSED
-> IDLE

============================================================
6. LIMIT SWITCH
============================================================

Wajib gunakan dua feedback:

- open limit switch
- close limit switch

State duct:
- OPEN
- CLOSED
- OPENING
- CLOSING
- UNKNOWN
- ERROR

Aturan:
- OPEN dianggap valid jika OPEN limit aktif.
- CLOSED dianggap valid jika CLOSE limit aktif.
- Jika kedua limit aktif bersamaan, anggap kondisi abnormal/error.
- Jika proses OPENING melebihi timeout tanpa OPEN limit:
  -> ERROR
  -> fan jangan ON.
- Jika proses CLOSING melebihi timeout tanpa CLOSE limit:
  -> ERROR.
- Servo harus berhenti ketika limit tujuan tercapai.

Jangan menggunakan timer sebagai pengganti limit switch.
Timer hanya boleh menjadi safety timeout.

============================================================
7. SERVO CONTROL
============================================================

Servo bukan actuator posisi permanen.

Servo digunakan untuk menarik tali mekanisme duct.

Konsep:
- OPEN: melakukan satu siklus tarikan.
- CLOSE: melakukan dua siklus tarikan.
- Setelah tarikan selesai, servo kembali/berhenti sesuai mekanisme.
- Limit switch menjadi sumber kebenaran posisi duct.

Jangan mengasumsikan duct berhasil hanya karena servo sudah bergerak.

Servo operation harus:
- punya timeout.
- berhenti ketika limit tercapai.
- memiliki state internal.
- tidak boleh dijalankan bersamaan dengan operasi servo lain.

============================================================
8. SAFETY INTERLOCK
============================================================

Implementasikan interlock berikut:

1. Direction relay tidak boleh berubah jika fan ON.
2. Fan tidak boleh ON jika duct belum OPEN.
3. Fan tidak boleh ON jika duct position UNKNOWN.
4. Jika OPEN dan CLOSE limit aktif bersamaan:
   - ERROR
   - fan OFF.
5. Jika servo timeout:
   - ERROR
   - fan OFF.
6. Jika terjadi MQTT disconnect:
   - jangan langsung mematikan fan kecuali memang sesuai requirement existing.
   - pertahankan desired state terakhir sesuai arsitektur existing.
7. Jika ESP32 restart:
   - fan OFF dahulu.
8. Semua state transition harus melalui state machine.
